# Product

## Register

product

## Users

People who use ChatGPT, Codex, and other AI tools on Windows and want to speak naturally instead of typing. They use the tool while an AI conversation is open and need a fast path from speech to the current input box, with a reliable manual copy fallback.

## Product Purpose

Voice to AI is a free Windows voice input tool for AI conversations. It records locally and uses either local Whisper or a user-configured audio transcription API. It attempts to paste the final text into the input field that was active before recording, with a manual copy fallback. API failures fall back to local transcription. Recognition, punctuation and semantic organization capabilities depend on the selected model; there is no mandatory task-draft template or separate text-rewriting step.

## Distribution Decision (2026-10-10)

All software features are free, with no subscriptions, paid unlocks or trial limits. Users can run local transcription without an API key; optional external API costs belong to their chosen provider. Distribution aims to build an audience through useful free tools, feedback and learning. Following the author is voluntary and must not gate downloads or use. Public release preparation still requires a distributable build, a selected open-source license and a clean release without personal recordings or credentials.

## Brand Personality

Lightweight, friendly, and slightly distinctive. The product should feel quick and dependable during repeated AI conversations, with clear feedback instead of technical clutter.

## Anti-references

Avoid copying Typeless branding, layout, wording, or visual assets. Avoid old desktop form styling, cramped controls, clipped fields, oversized panels, and interface text that mixes Simplified and Traditional Chinese.

## Design Principles

1. Keep the spoken source visible and recoverable at every step.
2. Make the fast path one shortcut and one result, with copy fallback when focus is uncertain.
3. Use semantic pauses and length limits to make local transcription readable without inventing content.
4. Show the source of the final transcript clearly and preserve copy fallback.
5. Favor clear contrast, generous click targets, and keyboard operation.

## Accessibility & Inclusion

Prioritize readable contrast, click targets large enough for repeated use, visible focus states, and keyboard activation for primary controls. Keep status changes explicit and avoid relying only on color.
